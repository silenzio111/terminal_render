将 Markdown 渲染到终端

不离开终端，
也能认真阅读 Markdown。

mdx 使用 Typst 将 Markdown 渲染为高清图像，通过 Kitty 图形协议直接显示在兼容终端中；它也能导出规整的 A4 或连续长页 PDF。

查看源代码了解设计思路

研发动机，是不让终端用户在阅读时退回到纯文本时代。

终端很适合写作、审阅版本差异和处理文件，但长篇 Markdown 一旦包含层级标题、表格、代码、图片或中文排版，原始标记会很快遮住内容本身。打开浏览器或单独的阅读器当然可行，却打断了本来连贯的命令行工作流。mdx 尝试保留终端的速度与可组合性，同时给文档一个值得阅读的视觉形态。

项目不把 Markdown 解释为需要“预览一下”的源代码，而把它看作可被完整排版的文档。使用者可以在 shell 中打开文件、翻阅渲染后的页面、保存时自动刷新，并在同一条路径上导出 PDF。目标不是替代所有编辑器，而是为习惯在终端里完成大部分工作的写作者和开发者补上阅读这一环。

技术链路把成熟的排版工具接入终端能力。

mdx 先由 Pandoc 把 Markdown 转换为 Typst 源码，再由 Typst 生成高分辨率 PNG 页面。终端展示使用 Kitty graphics protocol，因此图像能够直接出现在 Kitty、Ghostty、WezTerm、rio 或 Otty 等兼容终端里，而不是退化为字符画或临时文件路径。该选择承认不同终端的能力差异，也让渲染效果有明确的质量下限。

核心程序使用 Rust 编写，主要原因是它适合处理终端窗口尺寸、信号、输入事件、外部进程和连续刷新这些对资源释放与错误处理要求较高的边界。翻页器维护阅读位置，文件监听模式在内容重新渲染后按阅读进度恢复；没有文件参数时，程序也能处理来自子进程的流式 Markdown，使终端中的生成式输出获得更可读的呈现。

排版与导出不是附加按钮，而是同一份文档的两个落点。

阅读模式强调屏幕上的连续反馈，PDF 模式则面向交付、归档和打印。mdx 使用固定版本的 Typst 论文模板导出正常 A4 分页，也允许导出一张连续长页；这样同一份 Markdown 不需要先在浏览器里截图、再手工拼接成文件。字体路径可以自定义，项目也提供面向中文正文与等宽代码的字体回退策略，尽量让不同机器上的结果保持可读。

macOS 还提供一个 Finder 集成应用，可以把 Markdown 文件直接交给 mdx PDF.app 处理并将结果写回源文件旁。它不是另一套渲染引擎，而是把已有的命令行能力接到图形桌面入口，方便不希望每次打开终端的使用者。

项目保持对运行环境的诚实说明。

mdx 依赖 Pandoc 和 Typst，并只在 Unix 类系统上工作；不支持 Kitty 图形协议的终端不会显示图像。与其提供看似通用却不稳定的降级体验，项目选择明确写出这些条件，让使用者知道应该安装什么、在哪些终端中使用，以及为什么某些环境不适合它。

安装依赖后执行 cargo build --release 即可构建命令行程序。README 说明了终端兼容性、字体目录、PDF 导出参数和 Finder 应用的打包方式。源码以 MIT 许可发布，欢迎将渲染主题、键位、字体策略或适配范围继续扩展。
